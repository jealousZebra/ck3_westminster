# Modding Westminster

Paths below are relative to the repository root. The playable mod is `westminster/westminster/`.
CK3 script and localization use UTF-8 BOM. Python and JSON use UTF-8. Test history edits in a **new campaign**.

## Where to edit

| Change | Source |
| --- | --- |
| Starting skills, traits, ideology or DNA binding | `westminster/data/character_overrides.json` |
| 2024 character roster, party leaders, extra characters | `westminster/tools/data/build_2024.py` (`PARTIES`, `EXTRAS`, `FORMER_PMS`, `ACTIVISTS`) |
| 1979 roster and important birth dates | `westminster/tools/data/build_1979.py` |
| 1945/1997/2010/2016 dates, leaders, cabinets, featured characters | `westminster/tools/data/era_definitions.py` |
| Modern-map seat assignment | `MANUAL` in `era_definitions.py`; inspect `westminster/data/snapshots/` after rebuilding |
| Likeness descriptions | `PEOPLE` in `build_likenesses.py`; historical descriptions in `era_likenesses.py` |
| Ideologies, attitudes, causes, party ranges | `westminster/tools/data/build_ideology.py` |
| Commons bills and voting | `westminster/westminster/events/wm_commons_events.txt`, `common/scripted_effects/wm_commons_effects.txt`, `common/script_values/wm_commons_values.txt` |
| Government/Brexit, movement, press | `westminster/tools/data/build_governing.py`, `build_movement.py`, `build_press.py` |
| Text | `westminster/westminster/localization/<language>/`; generated text lives in its builder |

A file starting with “Generated by” is an output: edit the named source and rerun it. Other CK3 files are edited
directly. You do **not** need to rebuild the map or whole UI to change a script or character stat.

## Character skills and attitudes

Find the history ID in `westminster/westminster/history/characters/` (search the name or its localization key).
Add an entry under `characters` in `westminster/data/character_overrides.json`:

```json
{
  "characters": {
    "wm_1997_tony_blair": {
      "skills": { "diplomacy": 16, "learning": 12 },
      "traits": ["diligent"],
      "ideology": "social_democrat",
      "notes": "Example balance edit; explain the choice in your PR."
    }
  }
}
```

Omitted settings keep their defaults. Skills are base values, before modifiers; traits are additive. Use CK3 trait IDs.
Ideology keys are in `IDEOLOGIES` in `build_ideology.py`; `wm_faith_not_stated` is the neutral exception.
These are gameplay settings, not factual assessments of the person.

| In game | CK3 history key |
| --- | --- |
| Charisma | `diplomacy` |
| Economy | `stewardship` |
| Security | `martial` |
| Spin | `intrigue` |
| Policy | `learning` |
| Stamina | `prowess` |

Rebuild the affected roster: `python3 westminster/tools/data/build_2024.py`, `build_1979.py`, or `build_eras.py`
(the last writes all four new starts). Rebuilding 2024 or 1979 title history requires running `build_eras.py`
afterwards to restore the other dated entries. JSON overrides apply to those generated rosters; handwritten royal
history is edited directly. Traits, party wings and events also affect behaviour. Ideology is CK3 faith: crossing the
floor or other gameplay can move it into the party's permitted range.

To change an **attitude definition**, edit `POLICY` (choices), `POLICY_ICON` and the matching policy tuple in each
`IDEOLOGIES` entry in `build_ideology.py`. Keep the tuple order aligned with `POLICY`; rerun that builder. An attitude
does not implement a law by itself: voting effects live in `script_files()` and `wm_ideo_values.txt` is its output.

## DNA and likenesses

For the existing generated likenesses, edit a person's hair, style, beard, face, baldness, etc. in `PEOPLE` or
historical `SPECS`, then run `python3 westminster/tools/data/build_likenesses.py`. The vocabulary tables at the top
of that script list valid values. Hair and beards also use generated portrait modifiers; changing DNA alone may not
change them. Glasses are recorded but hidden by default (`SHOW_GLASSES`).

For hand-authored DNA from CK3's portrait editor, put a named `portrait_info = { genes = { ... } }` entry in a new
`westminster/westminster/common/dna_data/wm_custom_dna.txt`, following the existing DNA file's structure. Set
`"dna": "wm_dna_your_entry"` in the character override and rebuild its roster. Avoid IDs already written by a
builder. Existing likeness hair modifiers still apply; adjust that character's appearance description if necessary.

Featured characters have a **separate selection-screen cache**. After changing one, start that bookmark in debug
mode, run `dump_bookmark_portraits`, then run, for example:

```sh
.venv/bin/python westminster/tools/ui/build_bookmark_screen.py --1997 --import-dump
```

Use `--1945`, `--1979`, `--1997`, `--2010`, `--2016`, or no year flag for 2024. Keep both exported source files in
`westminster/art/bookmark_portraits/` and generated caches in the mod. Never construct these caches from genes alone:
CK3 needs its entity and tag data too. Restart CK3 to check the selection-screen result.

## Add a character

For a historical MP, update the source roster/mapping and featured lists as appropriate; snapshot JSON files are
outputs, not roster inputs. For an additional 2024 landless character, follow an `EXTRAS` or `ACTIVISTS` entry in
`build_2024.py`. Add the likeness before regenerating character history if it should get generated DNA.

For a standalone fictional character, add a new handwritten `history/characters/wm_your_characters.txt` with an
unused `wm_` ID, name localization, birth, culture and ideology. Use `set_variable = { name = wm_party value =
title:k_party_labour }` in a dated effect for party membership; use `wm_party_sync_house_effect = yes` there to align
the party house. Landing an MP also needs a dated county holder in title history: replace an existing seat holder,
do not add a 651st constituency. Check the party/cabinet and election setup if changing a leader.

## Add a policy

For a decision or event action, create a small handwritten `wm_<feature>` decision/event file, put reusable work in
`common/scripted_effects/`, and add localization in all nine languages. Existing desk actions are generated; edit
their builder to add an option. Reuse `wm_governing_change_effect = { KEY = wm_gov_services AMOUNT = 5 }` for a bounded
service change; call `wm_governing_ensure_effect = yes` first. State the scope of any new scripted effect in a comment.

For a **Commons bill**, follow an existing bill end to end:

1. Add the PM's choice in `wm_commons.1`; introduce it with a new `TYPE` and open `wm_commons.2`.
2. Add its lean/controversy branch in `wm_commons_setup_business_effect`, and its consequences in
   `wm_commons_bill_passed_effect`. Handle both full and conceded strength.
3. Add bill names/descriptions to the three event description selectors in `wm_commons_events.txt`, and localization.
4. Update ideology voting rules in `build_ideology.py` if attitudes should affect this bill. Test passage, defeat and concessions.

IDs 1–4 are ordinary bills, 5 is confidence, 6 is Brexit. **Use 7 onwards** for new bills. The fallback branches
currently assume confidence during setup and emergency powers on passage: add explicit branches before them.
Search `wm_commons_bill_type` before changing a bill ID. Government programme spending uses bill 2.

## Check your change

```sh
python3 common/tools/ck3_checks.py static westminster/westminster
python3 westminster/tools/data/test_character_overrides.py
python3 westminster/tools/data/test_eras.py
python3 westminster/tools/data/test_stability.py
```

Then load the affected start and inspect `error.log`. See [testing](ck3-testing.md) for the engine suites and
[contributing](../CONTRIBUTING.md) for PRs. Build prerequisites and downloads are in
[the mod README](../westminster/README.md#setup-install-and-test) and [source data notes](../westminster/data/README.md).
